# Architecture

## Runtime assets

`index.html` owns the page markup, including the primary Blending/What-if/Inventory/Settings/About navigation, screen panes, static Settings controls, the static About pane (credits, issue-tracker links, and the runtime third-party SBOM table; update it when CDN assets in `<head>` change), and relative asset references. `css/app.css` contains theme color variables for both appearances and custom table/scrollbar rules. The page loads Tailwind from its existing CDN, then `js/tailwind-config.js` maps utility colors to those variables, followed by the native-module entry `js/main.js`.

## JavaScript boundaries

- `js/main.js` owns browser event delegation, including primary-screen navigation, equipment-clone behavior, editable Inventory state, settings drafts, preset-import file/URL loading and immediate persistence, active theme, selected result tab, form parsing, supported-range validation, and calculation orchestration.
- `js/navigation.js` validates and applies the Blending/Inventory screen selection, including hidden-pane state and `aria-current` navigation state.
- `js/main.js` owns browser event delegation, including equipment-clone behavior, editable bank state, settings drafts, preset-import file/URL loading and immediate persistence, active theme, selected tab, form parsing, supported-range validation, and calculation orchestration.
- `js/compare-recipe.js` defines in-memory ordered Keep, Add gas, and Wait rows; Add gas may select a finite enabled named Supply bank or the unlimited 21/0 Compressor Air source; it validates linked Add pressure fields and target-temperature waits, copies finite selected-bank inventory for local planning, and selects Decant, Equalize, Boost, or compressor Top-up stages before simulation.
- `js/ui/compare-recipe.js` renders and updates the Compare-row editor, including the Compressor Air option, enabled named-bank selection, inferred source details, synchronized pressure controls, fixed-minute/target-temperature Wait fields, inline validation feedback, and modeled manual-recipe result cards.
- `js/theme.js` loads and saves the explicit light/dark choice in browser `localStorage`; light is the default.
- `js/materials.js` is the single source of truth for cylinder material values, labels, and thermal parameters; preset and input validation, the thermodynamic model, unit labels, and the Settings material select all read from it.
- `js/bank-storage.js` validates, loads, and saves the editable non-Air supply-bank list in browser `localStorage`; it migrates the previous built-in Helium/Tx 18/45/Oxygen list to the current defaults, discards legacy finite Air records, and allows an empty list.
- `js/settings.js` defines and validates the default gas/cylinder presets, the persisted `pressureLimitMode` (`hard-stop` by default), and the persisted boolean `pressureWarningUnlocked`; Warning is valid only after the case-insensitive confirmation phrase, with straight-quote/backtick/double-quote apostrophe variants accepted, and the phrase itself is never stored. It persists user-configured settings in browser `localStorage`, defaults legacy cylinders without the new field to 2%, migrates legacy volume-only and equipment-collection settings, and reports when unreadable saved data falls back to defaults.
- `js/preset-import.js` normalizes gas, cylinder, and combined equipment JSON sources, validates candidates, applies category-specific duplicate policies (gas by content; cylinders and equipment by normalized name), and immutably merges selected new presets without DOM dependencies. Repository-compatible defaults live in `presets/`.
- `js/gas-input.js` parses slash-delimited O₂/He paste input and provides strict numeric parsing and gas-composition validation without DOM dependencies.
- `js/input-validation.js` enforces supported calculator ranges, validates hot-overfill settings, applies Hard stop cylinder enforcement versus Warning reporting to pressure checks (measured pressure above working pressure is allowed within hot-overfill only in Hard stop), and validates supply-bank records; normal supported field bounds remain active in Warning.
- `js/pressure-limits.js` is the shared pure helper for applicable cylinder ceilings, exceedance classification, and thermal observation phases; `main.js` uses it to collect policy-aware result notices.
- `js/physics.js` contains pure gas-property functions, including compressibility-factor calculation from an already-known density; it has no DOM dependency.
- `js/thermodynamics.js` simulates configured-rate draining and transfer rates, numerically integrates signed pressure-change heating/cooling with ambient heat loss, records minute-resolution transfer samples, applies post-transfer Newton cooling and configured waits, and accepts transient measured pressure/temperature overrides before any protocol step; it returns thermal values alongside each step plus final transfer-end and ambient-settled estimates. For the Water medium it blends wet and dry surfaces in parallel from `waterSubmersionPercent` (`WATER_SUBMERSION_PERCENT_OPTIONS` 20/40/60/80, `DEFAULT_WATER_SUBMERSION_PERCENT` 60): the transfer heat-transfer coefficient and `1/τ` in `coolingTimeConstantMinutes` are linear in the wet fraction; Air ignores the percentage. `input-validation.js`, the Blending `#water-submersion` select, and the What-if editor/snapshot share these constants.
- `js/optimizer.js` validates the gas model, calculator ranges, user bank records, physical gas compositions, and thermal equipment input before constructing requested-mix and maximum-pressure programs; it propagates the selected pressure-limit mode, injects unlimited compressor Air, enforces the shared booster minimum source pressure, caps compressor and non-Air boost stages independently, and checks actual ambient-temperature states against working pressure while allowing only above-ambient transient states the configured hot-overfill limit in Hard stop mode. Warning mode reports cylinder exceedances without relaxing equipment or supported-input constraints.
- `js/onboarding.js` defines the validated, persisted consent and tour-seen state plus the ordered eight tour steps; this onboarding state is separate from calculation settings.
- `js/analytics.js` injects the Google Analytics tag once, and only after the visitor accepts consent.
- `js/ui/onboarding.js` renders the consent dialog and guided spotlight tour, navigates the primary screen required by each step, handles its focus, keyboard, persistence, narrow-viewport, and reduced-motion behavior, and requests the result tab or Settings category required by each step.
- `js/ui/settings-dialog.js` renders the Settings screen's persisted gas-model choice, editable gas and cylinder preset lists with working-pressure and hot-overfill controls, compressor and booster preset selectors, active equipment fields, the Preset management importer, and refreshes cylinder and gas choices.
- `js/ui/equipment-summary.js` renders the active compressor and booster names plus compact fill, boost, decant, and pressure-ceiling parameters below the supply-bank controls; unmatched active values are labeled Custom.
- `js/ui/storage-warning.js` renders persistence and rejected-bank-edit warnings from controller state.
- `js/ui/supply-banks.js` renders editable non-Air bank properties and gas-preset selectors; compressor Air is implicit and is not shown as a bank row, while derived N₂, Z, and minimum-pressure columns are not shown.
- `js/ui/results.js` renders gas metrics and the pumping protocol, including formatted Boost/Decant/Equalize/Top-up instructions, end-of-stage pressures/mixes, oxygen-rich compression ratios, source-end pressures and exhausted-source warnings, thermal rate/transfer-end/wait estimates, collapsed interim-reading controls between steps, final hot and ambient-settled pressure summaries, and explicit infeasible feedback.
- Salvage cards in `js/ui/results.js` list the receiver bank, helium moved, and the receiver's pressure and mix before and after the transfer. Salvage steps have no interim-reading slot, and the helium salvaged metric is unchanged.
- `js/interim-check.js` validates a manually recorded interim reading against the plan produced from the readings before its step: it rejects temperatures below ambient unless the gas came from a pressure-lowering drain or a salvage transfer out of the working tank, and rejects pressures outside the configured interim pressure tolerance. Stored readings are never mutated by the check.
- `js/plan-with-readings.js` is the single planner for recipes with interim readings. It takes the base plan from `optimizeBlend` with no readings, then applies each stored reading in ascending step order. For a reading at logical step k it derives the tank mix and the moles added by the transfer before k from the measured pressure and temperature, reduces the source bank by those moles, and runs `optimizeBlend` from that state. The steps before k and the re-planned steps are merged as the optimizer's pre-schedule logical steps and trajectory (exposed as `logicalPlan` on optimizer results), and `finalizeComposedPlan` schedules and simulates the merged recipe once, with every reading applied at its logical step, so cards, charts and the summary come from one simulation. Retained fraction, vented moles and helium salvaged are carried as a ledger across segments. `main.js` and `js/interim-check.js` both call it, so a later reading is verified against the recalculated recipe. Optimizer protocol steps carry `sourceBankId` for the bank mapping.
- In re-plans, `js/plan-with-readings.js` seeds each bank segment from the base plan's `salvageBanks` (the post-salvage inventory, or the input banks when no salvage ran) and runs every suffix optimization with `_salvage: false`. A re-plan therefore never salvages again, and a drain it creates stays vent-only.
- Reading indices are logical step indices and stay stable because readings are recorded in order: only the latest reading can be changed or cleared (`interimMeasurementLockMessage` in `js/interim-measurements.js` and the apply/clear paths in `js/main.js`), any recipe or settings change clears every reading, and the recipe is always recomputed from the whole stored list rather than patched. Weakening either rule would need explicit anchor IDs for readings.

Pressure-limit policy is propagated with the collected calculation input into Optimize and Compare. The shared helper maps observed initial, target, transfer, settled, and measured states to the applicable cylinder ceiling (working pressure at ambient/settled/target temperature; hot-overfill only for above-ambient transients) and classifies exceedances. In Warning mode, `main.js` attaches those observations to the calculation result; `js/ui/results.js` renders an amber active-policy notice even without an exceedance, and visible notices identifying measured pressure, threshold, kind, and input/step for actual exceedances on calculator and What-if/Compare result surfaces. The policy does not bypass supported 350-bar bounds, the calculator's 10-bar target minimum, or compressor/booster caps.
- `js/ui/thermal-charts.js` converts the completed thermal protocol into elapsed-time step-start, transfer-end, and ambient-settled key points plus minute-resolution transfer and cooling samples, then renders synchronized temperature and pressure SVG paths. The temperature plot includes a labelled dashed ambient-temperature reference line. Hovering either plot interpolates the sampled series at the pointer time, updates one shared time/temperature/pressure readout, and moves guide markers across both charts. Key points remain highlighted and populate the accessible data table; sampled paths follow the thermodynamics model between them. Alternating bands span each displayed step's transfer-plus-wait interval, and their captions alternate between two rows. Chart points and table rows share point indices and synchronize hover/focus highlighting. It includes drain preparation, omits the preserve-only no-op, and stops at the final ambient-settled state.
- `js/ui/ternary.js` shades the gray complementary N₂/Air/He region, draws dashed Air/O₂/He and full-simplex boundaries, reports composition under the pointer, populates the Tank summary tab's keyboard-operable O₂/He tables for reference mixes and trajectory data with source-bank start/end pressures, observes its container size, and bounds path-centered wheel and button zoom using the active theme's chart colors.

Calculation modules pass plain values to UI modules. UI renderers own only their assigned DOM surface. Primary screen controls are handled by `js/navigation.js`; Inventory controls are generated dynamically and handled by delegated events in `main.js`; bank names are treated as text. Preset edits remain transient drafts until the user saves settings, while confirmed preset imports immediately write the merged settings to `localStorage`. Settings category selection is transient UI state. Onboarding consent and tour-seen state is stored separately from calculation settings, and accepting consent is the only path that loads the Analytics tag. Selecting a cylinder preset supplies the working tank's volume, material, mass, working pressure, and hot-overfill percentage, while a gas-bank preset also updates that bank's displayed name.

## Data flow

1. The settings dialog edits the gas model, gas and cylinder presets, named equipment collections, and active equipment-setting drafts through transient category panes; category-specific clone actions append uniquely named copies of the active compressor or booster values without changing those active values. Saving validates and persists the draft in `localStorage`. Preset management loads JSON from a local file or editable online URL, previews valid new entries alongside disabled content/name duplicates and invalid gas name conflicts, and immediately persists confirmed selections through the same settings storage path. Legacy volume-only settings are normalized into cylinder presets when loaded. `bank-storage.js` loads saved non-Air bank records, removes legacy Air records, and writes user-bank mutations for the next session.
2. On first load, `main.js` reads the separate onboarding state. Without consent it opens the consent dialog and does not load Analytics. If persisting accepted consent fails, the dialog remains open with a visible error and Analytics stays disabled; otherwise acceptance persists consent, clears any stale onboarding storage warning, injects the Analytics tag, and opens the tour. With consent but no seen tour it opens the tour directly. Done, Skip, and Escape during the tour each persist the seen state, so no dismissed or completed tour is reopened automatically; Escape during consent leaves the consent gate visible and does not persist a dismissal. A successful factory reset clears all stored data, resets live onboarding state to no consent and no seen tour, and reopens the consent gate. The header wand re-enters the tour at its first step, "Main menu". Tour navigation selects the primary screen, Settings category, or result tab required by each step's target.
3. `main.js` applies the saved theme to the root element; CSS variables update app colors, and the ternary canvas redraws after theme changes.
4. A form, bank, gas preset, cylinder preset, physics-setting, or main-screen tank thermal-input change causes `main.js` to collect one input object. Interim readings are transient state keyed to the next protocol step and bound to the current recipe signature; changing recipe or equipment inputs clears them before recalculation. Applying a valid reading sends its pressure and temperature to the thermal simulator, while the planned gas recipe remains unchanged. The browser uses the selected cylinder preset for working-tank volume, material, mass, working pressure, and hot-overfill validation; it uses the saved gas model and maps ambient temperature to both `physics.temperatureC` and `thermal.ambientTemperatureC`; inlet gas temperature remains independent.
5. In Optimize mode, `optimizeBlend` propagates the selected pressure-limit mode, injects unlimited 21/0 compressor Air, enforces the configured compressor and non-Air booster ceilings, calculates gas quantities and bank availability, solves for the requested exact mix, then finds a maximum recipe for that same mix if the requested pressure is unavailable. Hard stop applies cylinder working-pressure/hot-overfill checks and can schedule waits or splits; Warning reports those exceedances without a cylinder-only wait. In Hard stop, ambient and final target-temperature pressures use working pressure as the ceiling; in Warning, they may exceed it and are reported as cylinder-limit observations without enforcement. Supported calculator bounds and equipment ceilings remain active.
6. In Compare mode, `main.js` collects in-memory rows and passes them with the current cylinder, thermal, equipment, and Supply-bank inputs to `compare-recipe.js`. Each Add row selects either an enabled named finite bank or unlimited 21/0 Compressor Air; finite planning copies source inventory, Compressor Air is constrained by the configured compressor pressure ceiling, modeled Wait state carries into later rows, and planning chooses Decant, Equalize, Boost, or compressor Top-up. The thermodynamic engine simulates the planned stages and fixed-minute or target-state waits. Neither the recipe nor local source consumption is persisted, and an invalid run retains the last successful Compare result.
7. `main.js` sends bank state to the bank renderer, active equipment settings to the equipment-summary renderer, and the selected mode's result to the results, thermal-chart, and ternary renderers. Compare results render a manual trajectory without bank-source metadata; Optimize retains its existing bank accounting and result presentation.
For Optimize results with an unavailable exact target, `main.js` passes `maximumPressure.trajectory` to the ternary renderers when present; invalid or no-positive-solution results still clear those surfaces.
8. Selecting the Diagram tab or resizing its container redraws the latest chart; its accessible data tables update with the same reference mixes and trajectory points. Selecting Thermal graphs shows synchronized temperature and pressure histories on a minutes-based X-axis, with both histories drawn from minute-resolution transfer/cooling samples while the three semantic key points per step remain highlighted and tabulated. Hovering either graph displays the interpolated time, temperature, and pressure and moves synchronized guide markers across both charts. Alternating bands and alternating caption rows separate displayed protocol steps. Both histories include drain preparation in Optimize, omit the preserve-only no-op, and stop at the final ambient-settled point; hover…

The app uses browser-native ES modules and has no bundling step. Serve the directory over HTTP; see [Development](development.md).

## What-if boundaries

What-if owns an independent scenario draft and terminal result projection; its result host and scoped renderers do not share Blending's result root. The draft snapshots start state while runtime reads current enabled banks and equipment/cylinder settings, without persistence mutation or inventory depletion. Manual rows are executed in order, including explicit waits, and the terminal projection feeds Scenario summary, Recipe, thermal, in-water, tank-summary, and Simplex renderers. Invalid reruns retain the last valid terminal projection and shared-input changes label it stale.
